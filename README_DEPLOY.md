# 🐷 Копилка — бот учёта трат (соло / пара по коду / групповой чат)

Бот: **@kopilka_vmeste_bot** · Стек: Telegram Bot API + Vercel Functions (вебхук) + Supabase (Postgres). Стоимость инфраструктуры на старте — 0 ₽.

## Что умеет

- **Соло**: пишешь боту в личку «кофе 350» — записывает.
- **Пара по коду**: один пишет `/link`, получает код вида `K7QM2X`; второй открывает бота в личке и отправляет `/join K7QM2X`. Дальше траты обоих падают в одну копилку, оба видят подтверждения и отчёты — групповой чат не нужен.
- **Семья/компания**: добавить бота в групповой чат, тратить прямо туда.
- Категории угадываются по словам (🛒 Продукты, ☕ Кафе…), сумму можно писать в любом месте сообщения, минус не важен.
- Лимиты по категориям (`/budget кафе 5000`), отчёты `/report` (месяц) и `/week` (7 дней), отмена траты (`/undo` или кнопка ↩️).
- Бесплатно — 30 трат в месяц на копилку. Премиум — **99 звёзд Telegram Stars** (≈ 99 ₽): без лимита + автоотчёт по воскресеньям в 19:00 МСК.

## Деплой за 20 минут: 4 шага

Бот «работает в Telegram», только когда есть HTTPS-адрес, куда Telegram присылает сообщения. Схема такая:

```
Telegram → вебхук на Vercel (api/webhook.js) → Supabase (БД)
                ↑ Vercel Cron (api/cron.js) — автоотчёты по воскресеньям
```

Понадобятся бесплатные аккаунты: **GitHub**, **Supabase**, **Vercel**.

### Шаг 1. База данных (Supabase, ~5 минут)

1. Зайди на [supabase.com](https://supabase.com) → **New project**. Имя: `kopilka`. Регион: Frankfurt. Пароль БД — сгенерируй и сохрани.
2. Открой **SQL Editor → New query**, вставь **весь** файл `schema.sql` из этого проекта, нажми **Run**. Ответ `Success. No rows returned` — значит, таблицы созданы.
3. **Project Settings → API**: скопируй два значения:
   - `Project URL` — это `SUPABASE_URL`;
   - `service_role` key (именно **service_role**, не anon!) — это `SUPABASE_SERVICE_KEY`.

### Шаг 2. Код на GitHub (~5 минут)

Распакуй архив `kopilka-bot.zip`, открой папку в терминале и выполни:

```bash
git init
git add .
git commit -m "Kopilka bot v1"
git branch -M main
git remote add origin https://github.com/<ТВОЙ_ЛОГИН>/kopilka-bot.git
git push -u origin main
```

(Репозиторий заранее создай на github.com, кнопка New repository.)

⚠️ **Если заливаешь файлы через сайт GitHub** (Add file → Upload files): перетащи **содержимое** папки `kopilka-bot` — папки `api`, `lib`, `scripts` и все файлы (`package.json`, `vercel.json`, `schema.sql` и др.), а не саму папку и не только верхние файлы. После загрузки на главной репозитория обязательно должны быть видны три папки: `api`, `lib`, `scripts`. Если их нет, задеплоится неполный проект и сборка упадёт с ошибкой `unused_function`. Если на главной репозитория видна одна папка `kopilka-bot` — ты перетащил саму папку: удали файлы и загрузи заново, выделив всё (Ctrl+A) **внутри** распакованной папки.

### Шаг 3. Деплой на Vercel (~5 минут)

1. [vercel.com](https://vercel.com) → **Add New... → Project** → импортируй свой репозиторий `kopilka-bot`. Framework Preset: **Other**, ничего не меняй.
2. Перед нажатием **Deploy** раскрой **Environment Variables** и добавь пять переменных:

| Имя | Значение |
| --- | --- |
| `BOT_TOKEN` | токен из @BotFather (тот, что у тебя уже есть) |
| `SUPABASE_URL` | Project URL из шага 1 |
| `SUPABASE_SERVICE_KEY` | service_role ключ из шага 1 |
| `WEBHOOK_SECRET` | любая длинная случайная строка |
| `CRON_SECRET` | другая длинная случайная строка |

3. Жми **Deploy**. Через минуту получишь адрес вида `https://kopilka-bot-xxxx.vercel.app` — запиши его, это `VERCEL_URL`.

### Шаг 4. Подключить бота к Telegram (~1 минута)

Открой в браузере (подставь свои токен, адрес и секрет из шага 3):

```
https://api.telegram.org/bot<ТОКЕН>/setWebhook?url=https://<ТВОЙ-АДРЕС>.vercel.app/api/webhook?secret_token=<WEBHOOK_SECRET>
```

⚠️ Это шаблон, а не готовая ссылка: каждый фрагмент в угловых скобках `<...>` надо **целиком заменить** (скобки удалить) на своё значение. Например, вместо `bot<ТОКЕН>` должно получиться `bot1234567890:AAExx...` — просто токен из BotFather, без скобок, пробелов и кавычек. `secret_token=` должен совпадать с переменной `WEBHOOK_SECRET` из Vercel символ в символ. Скопируешь ссылку как есть со скобками — Telegram ответит `404 Not Found`.

Должно появиться `{"ok":true,...}`. Всё — бот живой.

Или автоматом: локально создай файл `.env` из `.env.example`, заполни (включая `VERCEL_URL`) и запусти `npm install && npm run set-webhook`.

### Шаг 5. Обязательные настройки в @BotFather (2 минуты)

1. **Выключить privacy mode** — иначе бот не увидит траты в группах: открой [@BotFather](https://t.me/BotFather) → `/setprivacy` → выбери бота → **Disable**. У нас на момент сборки он был **включён** (`can_read_all_group_messages: false`), так что этот шаг обязателен.
2. Список команд (`/setcommands`) я уже зарегистрировал через API — пункты меню у бота появятся сами. Если выпустишь новый токен, повтори `/setcommands` или скажи мне.
3. После этого перейди по ссылке из шага 4 **ещё раз** (setWebhook идемпотентен) или сразу проверь `npm run check-webhook`.

## Проверка (чек-лист)

1. В личке у бота: `/start` → приветствие. Напиши `кофе 350` → ответ `✅ 350 ₽ — ☕ Кафе и рестораны` с кнопкой ↩️.
2. `/report` и `/week` — отчёты не пустые.
3. Парный режим: `/link` → код. Со второго аккаунта (или с телефона друга): `/join КОД`. Оба получают «Готово!». Теперь траты обоих идут в одну копилку.
4. Группа: создай чат, добавь бота, напиши `обед 500`. Если бот молчит — privacy mode всё ещё включён (см. шаг 5).
5. `/budget кафе 5000`, затем набей трат по кафе больше 5000 — придёт предупреждение ⚠️.
6. `/premium` — появится счёт на 99 звёзд (для теста нужно купить звёзды в Telegram, ~99 ₽; можно отложить и протестировать позже).

## Локальная разработка

```bash
npm install
cp .env.example .env   # заполни BOT_TOKEN, SUPABASE_URL, SUPABASE_SERVICE_KEY
npm run dev            # long polling, вебхук не нужен
```

⚠️ Polling и вебхук одновременно не работают (ошибка 409 Conflict). Пока бот задеплоен на Vercel, локальный `dev` сначала удали вебхук: `https://api.telegram.org/bot<ТОКЕН>/deleteWebhook`, после отладки верни командой `npm run set-webhook`.

## Деньги: как 99 ₽ превращаются в твои 99 ₽

- Сейчас оплата — **Telegram Stars (XTR)**: счёт на 99 звёзд, кнопка прямо в боте, ноль документов и касс. Цена задаётся в `lib/config.js` (`PREMIUM_PRICE_STARS`).
- Звёзды выводятся через Fragment в TON с потерей на комиссиях (примерно 25–30% по пути до рублей) — для старта приемлемо, но знай.
- Когда пойдёт поток: зарегистрируй самозанятость (0 ₽, через приложение «Мой налог»), подключи **ЮKassa для самозанятых** (комиссия ~3,5%) — приём картами РФ по честным 99 ₽. Налог НПД — 4% с выручки от физлиц.
- Смена цены: одна константа в `lib/config.js`, деплой пересоберётся сам.

## Частые ошибки

| Симптом | Причина и лечение |
| --- | --- |
| Сборка Vercel падает: `unused_function: The pattern "api/cron.js" ... doesn't match any Serverless Functions` | В репозитории нет папки `api/` — на GitHub залиты не все файлы. В логе сборки это видно по строке `Downloading N deployment files` (должно быть ~20, а не 5–8). Загрузи в репозиторий всё содержимое проекта: папки `api`, `lib`, `scripts` и файлы из корня — и сделай Redeploy |
| Деплой Ready, но `<адрес>/api/webhook` даёт `404 NOT_FOUND` | Функции не задеплоились: папки `api/` нет в репозитории, или весь проект лежит внутри вложенной папки-обёртки. Открой главную страницу репозитория — на верхнем уровне должны лежать `api`, `lib`, `scripts` и файлы, а не одна папка `kopilka-bot` |
| `api.telegram.org/bot<TOKEN>/setWebhook...` отвечает `404 Not Found` | Плейсхолдер `<TOKEN>` не заменён настоящим токеном. Удали скобки `< >` и вставь полный токен из BotFather (вида `1234567890:AAE...`), без пробелов и кавычек |
| `git commit` падает: `Author identity unknown` / `Please tell me who you are` | Git не знает, кого указать автором коммита. Один раз выполни `git config --global user.name "твой_логин_github"` и `git config --global user.email "логин@users.noreply.github.com"`, затем повтори `git commit` |
| `git push` падает: `src refspec main does not match any` | Коммит не создался (см. строку выше) — пушить нечего. Сначала `git commit -m "..."`, потом `git push` |
| `git remote add origin ...` отвечает `remote origin already exists` | Не поломка: адрес уже прописан. Пропусти эту команду и сразу делай `git push` |
| `git push` отвечает `rejected ... non-fast-forward` / `fetch first` | На GitHub уже лежат файлы, залитые через сайт, а локальная история с ними не связана. Для первого пуша безопасно: `git push -u origin main --force` — веб-версия перезапишется полной локальной |
| `{"ok":false,"error_code":401}` на любом запросе | неверный токен — проверь BOT_TOKEN |
| Бот молчит в группе | privacy mode включён → BotFather `/setprivacy` → Disable |
| `409 Conflict` в логах Vercel | где-то запущен `npm run dev` (polling) параллельно с вебхуком — останови его |
| Vercel Function logs: `SUPABASE_URL и SUPABASE_SERVICE_KEY должны быть заданы` | переменные не добавлены в Environment Variables — добавь и сделай Redeploy |
| Вебхук установлен, бот не отвечает | `npm run check-webhook` — покажет `last_error_message`; чаще всего неверный `WEBHOOK_SECRET` в URL |
| Автоотчёты не приходят | сегодня не воскресенье (штатно), или у копилки нет премиума, или CRON_SECRET не совпадает |
| Превышен бесплатный лимит Supabase | маловероятно до десятков тысяч трат; следующий тариф — 10$/мес, к тому моменту премиумов хватит на покрытие |
